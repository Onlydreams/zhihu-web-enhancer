# zhihu-web-enhancer

一个基于 [XIU2/UserScript](https://github.com/XIU2/UserScript) 中
[`Zhihu-Enhanced.user.js`](https://github.com/XIU2/UserScript/blob/master/Zhihu-Enhanced.user.js)
的非官方知乎网页增强 Userscript 衍生维护仓库。

- 上游脚本版本：`2.3.32`
- 当前脚本版本：`2.3.40`
- 上游 commit：`77b9f742b2c291b2908bd092a1805783e78747d7`
- 导入日期：`2026-08-06`
- 基线提交：`f0735468cc2d5f7480a60d8ded53ff96b2de136c`

当前脚本已经使用独立身份：

- 名称：`知乎网页增强（Onlydreams 维护版）`
- namespace：`https://github.com/Onlydreams/zhihu-web-enhancer`
- 项目：`https://github.com/Onlydreams/zhihu-web-enhancer`
- 反馈：`https://github.com/Onlydreams/zhihu-web-enhancer/issues`

它不会覆盖官方“知乎增强”，但两个脚本同时启用会重复处理同一页面。迁移完成后应停用原版，
当前仍不要把 `main` 分支当作稳定发行版。

## 项目目标

在保留上游现有功能和设置习惯的前提下，维护个人实际使用中需要的网页适配与功能补充。

首个衍生功能让现有“屏蔽指定关键词”能力覆盖知乎“等你来答”页面
（`/question/waiting`）的全部问题列表：

- 直接复用 `menu_blockKeywords` 和 `menu_customBlockKeywords`；
- 按不区分大小写的字面子串检查问题标题，不折叠空白、不裁剪已有词条；
- 同时处理初始列表和后续动态加载的问题；
- 命中后只在本地隐藏完整问题卡片；
- 不点击“不感兴趣”，不向知乎提交推荐反馈；
- 不新增知乎 API 调用或其他网络请求。

过滤覆盖“为你推荐”“邀请回答”“最新问题”和“人气问题”四个分类，不依赖分类 `type` 或当前选中标签。

问题页会在首次绘制前根据现有用户黑名单生成本地 CSS，尽量避免被屏蔽回答先显示、随后再消失；
原有 MutationObserver 仍负责兼容动态加载及不支持早期 CSS 的场景。
编辑名单、通过按钮添加或取消屏蔽、关闭用户屏蔽时会同步重建或移除这份 CSS；
已有内容如果被 JavaScript 隐藏，仍需刷新才能重新显示。

维护版还对继承实现做了小范围硬化：首批元素等待具有明确间隔和停止上限，MutationObserver
不会因同批次中的文本节点跳过后续元素，收起回答观察器可在 SPA 页面往返后重新启动；站外直链仅接受
有效的 HTTP/HTTPS 目标，畸形或其他协议链接保持原样。

`2.3.36` 修复热榜动态过滤遗漏与文本节点异常、高亮链接在混合批次和包装节点中的清理遗漏，
以及评论同时命中多个关键词后无法恢复原文的问题。邀请区只在具体问题/回答页等待加载，
每 100 毫秒检查一次、最多等待 5 秒，路由变化时取消；超过等待窗口仍未出现的邀请区保持原样。
热榜过滤与悬浮评论关闭按钮查找在每批 DOM 变化中最多执行一次。图片、外链和时间的现有轮询机制保持不变。

`2.3.37` 修复已复现的安全、健壮性和过滤问题：

- 用户主页、悬浮卡的屏蔽按钮和问题作者使用 DOM 属性与文本赋值，昵称、作者 token 和头像不会被拼入 HTML；头像只接受 HTTP/HTTPS。
- 登录提示仅在新增节点自身及子树中定位，避免误删其他内容；高亮清理只替换链接，保留周围文字。
- 缺少搜索框、主页节点或角落按钮不再中断启动；功能初始化异常记录功能名和错误，后续功能继续执行。主页路径不再通过 URL 中的 `org` 子串判断。
- 空词表仍安装标题/评论监听；添加首词后过滤新内容，关闭开关后停止过滤新内容。热榜关键词过滤覆盖动态卡片及包装节点，默认收起不会跳过同批次其他回答。
- “等你来答”覆盖标题后填、文本更新、列表替换和同 URL 下根节点重挂，包括发现阶段尚无列表的情况；复用列表/根和同批多次替换的遗漏在 `2.3.38` 补齐。增量过滤仅检查受影响卡片，恢复时保留原有隐藏状态和 display。
- 首页、评论和“等你来答”统一使用字面子串匹配。例如 `牢 A` 不命中 `牢   A`；从选区添加新词仍压缩空白，但不改写原有词表。
- 账号级屏蔽沿用已有请求，显式处理 HTTP 失败、网络错误、超时和取消；本地名单先保存，远端失败不回滚，并分别报告两侧结果。主页刷新在请求结果后进行。
- 菜单重注册清理旧 ID；首批等待超时后，直达问题和类别过滤仍处理动态锚点自身及包装节点。

`2.3.38` 补齐独立复审发现的边界：

- “等你来答”重挂时即使复用原列表或原根，也会更新根和祖先订阅；旧空根保留时列表搬移或移除也会重连/重新发现。同批曾添加、随后已移除的过渡列表不再成为监听目标。
- 列表晚到时，现有祖先监听也检查直接新增子树，覆盖主区域外直接挂入 body 的列表或包装节点。
- 类别过滤遇到缺少卡片或回答祖先的节点时保持原样，同批后续合法卡片继续处理。
- 作者头像兼容 `//`、根相对和路径相对 HTTP/HTTPS 地址；空值、畸形地址和其他协议保持无 src，不把空地址解析为当前页面。

`2.3.39` 在修复基线后单独进行结构整理：

- 普通样式共用 `appendStyle` 入口，保留原 CSS、挂载位置和追加顺序；首帧名单样式仍由自身生命周期管理。
- 初始化错误标签统一为函数名，过滤函数带场景，例如 `blockKeywords(waiting)`；保留原始错误和隔离语义。
- 原 `review-regressions.test.js` 按黑名单、作者、关键词、waiting 生命周期、启动、收起、类别与 DOM 清理拆分，共用 waiting 夹具；既有用例保持。

结构整理保持单文件、现有存储键和过滤语义。

`2.3.40` 修复脚本直接删除或重建知乎节点导致的 React 更新冲突：

- “移除高亮链接”保留原链接和子节点，通过样式取消高亮，并在捕获阶段阻止点击、修饰点击和中键跳转；动态链接沿用同一委托。保留的 href 仍可被浏览器右键菜单读取。
- 首页导航和回答页“查看全部回答”保留原节点，通过事件委托实现整页导航；保留修饰键、中键、target 和 download 的原生行为。“推荐”在有效左键/中键点击时沿用原 cookie 语义。
- 搜索视频、首页视频回答及热榜非问题项改为隐藏完整卡片，不删除卡片或回答正文；类别过滤以内联 `display: none !important` 保证隐藏不被普通页面样式覆盖。
- 登录弹窗沿用页面关闭按钮；“立即登录/注册”只隐藏已识别的提示区或按钮，保留普通包装内容。顶部登录入口保留原按钮，点击打开登录页。
- 评论关键词过滤保留原正文、链接、图片和事件，在旁边增加脚本自己的占位按钮；点击后恢复原 display 和优先级。正文单独移除或搬移时，原观察器清理配对占位。
- 直达问题不再重解析标题或替换英文问号；邀请折叠增加自己的按钮，保留原标题和事件。
- 时间和热榜排名只更新已有单个 Text 节点的值；遇到子组件、图标或其他复杂结构时保持原文，不强行展开时间或改写排名。

本次保持单文件、现有存储键及名单兼容，不增加知乎 API 调用或账号操作。菜单开关仍按提示刷新后完整生效。

观察器整合及性能重构留待真实页面测量：waiting 优先在主区域发现列表，发现后断开发现观察器；
主区域尚未出现时仍用 body 作为临时发现范围。主区域存在时，祖先仅观察直接子节点变化；
未覆盖已有主区域外兄弟子树深处后来挂入列表的布局，需真实页面证据再扩展适配范围。
未对首帧 `:has()` CSS 或继承的轮询作性能验收。

## 安装与配置迁移

新名称和 namespace 会让 Tampermonkey 将维护版识别为独立脚本。原版的 `GM_*` 配置不会自动复制，
也不能由维护版直接读取。建议按以下顺序迁移：

1. 保持原版启用，打开任意知乎页面。
2. 在 Tampermonkey 的原版“知乎增强”菜单中打开“自定义屏蔽用户”；在弹窗中全选并复制完整内容，然后点“取消”。如果菜单不存在，先记录当前开关状态，临时开启“屏蔽指定用户”并刷新页面。
3. 同样复制“自定义屏蔽关键词”的完整内容；关键词之间的 `|` 分隔符需要保留。如果菜单不存在，临时开启“屏蔽指定关键词”并刷新页面。
4. 记录原版菜单中各功能的开关状态，以及“屏蔽低赞低评”和“屏蔽指定类别”中的自定义选项。
5. 安装本维护版，先停用原版，避免两个脚本同时修改同一个知乎页面。
6. 在维护版菜单中分别粘贴自定义屏蔽用户和关键词，并按记录恢复其他开关与数值。
7. 刷新知乎，检查普通信息流和“等你来答”的四个分类；确认无误后再决定是否删除原版。

迁移过程中不要先删除原版。Tampermonkey 中停用的原版可作为配置备份，出现遗漏时可以随时重新启用核对。

从 `2.3.36` 或更早维护版升级时，“等你来答”不再折叠标题和词条中的空白，改为与首页、评论相同的字面匹配；
已有词表原样保留。若曾依赖 `牢 A` 命中 `牢   A`，需要按实际标题手动补充对应词条。

从 `2.3.39` 或更早维护版升级到 `2.3.40` 时，沿用原维护版脚本的配置。
若此前为避开问题页报错而关闭“移除高亮链接”，更新脚本后可重新开启并刷新，再检查回答展开/收起。

## 上游已有能力

当前维护版从上游基线继承的主要能力包括：

- 按用户、关键词、内容类别、赞同数和评论数过滤内容；
- 通过 Userscript 菜单维护屏蔽用户、屏蔽词及功能开关；
- 收起回答与评论、快捷返回顶部；
- 清理登录弹窗、高亮链接、搜索热门和标题消息；
- 展开问题描述、显示问题作者和完整时间；
- 使用原图、处理站外直链，以及区分问题与文章等。

完整行为以仓库根目录的 [`Zhihu-Enhanced.user.js`](./Zhihu-Enhanced.user.js) 为准。

## 开发与验证

本项目保持单文件、零构建、零运行时依赖。修改后至少运行：

```powershell
node --check .\Zhihu-Enhanced.user.js
node --test
git diff --check
```

涉及页面选择器、动态加载或内容过滤时，还应在 Tampermonkey 中完成对应页面的手工验证。
语法检查不能替代浏览器功能验证。

回归测试使用 Node 内置测试框架，通过 `test-support/userscript-harness.js` 将完整脚本加载到 VM，
提供最小 DOM、定时器、菜单、请求桩和按实际订阅范围派发的观察器入口；不再按源码中的大括号字符提取函数。
行为用例主要覆盖昵称安全赋值、名单与 CSS 同步、请求结果分流、空词表、动态热榜、关键词语义、初始化隔离、
回答收起批次、邀请区等待，以及 waiting 文本变化、列表/根重挂、复用、同批多次替换和追加卡片不重扫旧列表等场景。
元信息、独立身份和首帧/常规启动的源码顺序仍使用源码断言，不能据此证明实际绘制时序。
关键标题/评论入口校验选择器字符串，但最小 DOM 不实现浏览器的选择器解析；上述模拟并未覆盖所有受改动功能的行为。
这些结果不代表浏览器 HTML/CSS 引擎、实际知乎 DOM 或脚本管理器权限已验证。
样式用例覆盖普通样式入口和首页真实初始化路径，检查 CSS 字面内容、`1500px` 最小高度、视频开关、挂载位置和追加顺序；
初始化错误用例检查场景标签。这些用例仍不执行浏览器 CSS 引擎，测试拆分没有扩大浏览器验证范围。

`2.3.40` 增加实际业务入口的节点身份、捕获/冒泡事件、动态导航、评论占位清理、样式优先级、
标题及邀请子节点、时间和排名叶文本用例。最小 DOM 现在模拟 HTML 赋值断开原节点，但仍不解析 HTML。
浏览器验证范围和结果另列于下面，不能由 VM 测试替代。

本次验证结果：

- 本地回归测试 `75/75` 通过；脚本语法检查及 `git diff --check` 通过。
- Chrome 中使用 React `17.0.2` 的最小浏览器对照调用实际脚本函数，再由 React 更新同一组件。旧版在高亮自动收起、导航、视频、热榜、登录、评论、标题、邀请、时间和 ViewAll 等 14 个结构破坏场景报错；修复后全部通过。
- 连同纯文本/HTML 内容对照及评论正文单独替换后的占位清理，共 `19/19` 个修复后场景无异常。原节点在 React 更新前保留；视频、热榜、登录提示和被屏蔽评论在显式作者 display 样式下实际计算为 `display: none`。
- 真实知乎问题页已确认旧版的 React `removeChild` 异常；关闭“移除高亮链接”并刷新后，用户确认恢复正常。当前修复尚未替换浏览器已安装脚本，上述浏览器夹具结果不等于 `2.3.40` 的真实知乎页面验收。

尚未完成 Tampermonkey 实测：昵称按钮与问题作者展示、账号请求结果通知、登录提示与高亮清理、
热榜动态加载、评论点击恢复、邀请区、悬浮评论关闭、类别过滤、回答/评论收起、标题/时间展示及样式挂载，
以及“等你来答”全部七项手工验收仍待验证：
四个分类首屏、滚动追加、SPA 首次进入、命中与未命中、关闭开关、编辑词表后的新内容，以及切换分类不影响其他问题页。
还需验证标题后填、同 URL 下页面根重挂和主区域外列表挂载。自动化测试不会实际调用知乎屏蔽接口。
本次环境中默认 `node --test` 因子进程 `spawn EPERM` 无法运行，使用
`node --test --test-isolation=none` 执行测试；该结果不代表真实浏览器兼容性验证。
