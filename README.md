# zhihu-web-enhancer

一个基于 [XIU2/UserScript](https://github.com/XIU2/UserScript) 中
[`Zhihu-Enhanced.user.js`](https://github.com/XIU2/UserScript/blob/master/Zhihu-Enhanced.user.js)
的非官方知乎网页增强 Userscript 衍生维护仓库。

- 当前脚本版本：`2.3.36`

- 导入日期：`2026-08-06`

当前脚本已经使用独立身份：

- 名称：`知乎网页增强（Onlydreams 维护版）`
- namespace：`https://github.com/Onlydreams/zhihu-web-enhancer`

## 项目目标

在保留上游现有功能和设置习惯的前提下，维护个人实际使用中需要的网页适配与功能补充。

首个衍生功能让现有“屏蔽指定关键词”能力覆盖知乎“等你来答”页面
（`/question/waiting`）的全部问题列表：

- 直接复用 `menu_blockKeywords` 和 `menu_customBlockKeywords`；
- 按现有关键词匹配语义检查问题标题；
- 同时处理初始列表和后续动态加载的问题；
- 命中后只在本地隐藏完整问题卡片；
- 不点击“不感兴趣”，不向知乎提交推荐反馈；
- 不新增知乎 API 调用或其他网络请求。

过滤覆盖“为你推荐”“邀请回答”“最新问题”和“人气问题”四个分类，不依赖分类 `type` 或当前选中标签。

问题页会在首次绘制前根据现有用户黑名单生成本地 CSS，尽量避免被屏蔽回答先显示、随后再消失；
原有 MutationObserver 仍负责兼容动态加载及不支持早期 CSS 的场景。

维护版还对继承实现做了小范围硬化：首批元素等待具有明确间隔和停止上限，MutationObserver
不会因同批次中的文本节点跳过后续元素，收起回答观察器可在 SPA 页面往返后重新启动；站外直链仅接受
有效的 HTTP/HTTPS 目标，畸形或其他协议链接保持原样。

`2.3.36` 修复热榜动态过滤遗漏与文本节点异常、高亮链接在混合批次和包装节点中的清理遗漏，
以及评论同时命中多个关键词后无法恢复原文的问题。邀请区只在具体问题/回答页等待加载，
每 100 毫秒检查一次、最多等待 5 秒，路由变化时取消；超过等待窗口仍未出现的邀请区保持原样。
热榜过滤与悬浮评论关闭按钮查找在每批 DOM 变化中最多执行一次。图片、外链和时间的现有轮询机制保持不变。

## 安装与配置迁移

新名称和 namespace 会让 Tampermonkey 将维护版识别为独立脚本。原版的 `GM_*` 配置不会自动复制，
也不能由维护版直接读取。建议按以下顺序迁移：

1. 保持原版启用，打开任意知乎页面。
2. 在 Tampermonkey 的原版“知乎增强”菜单中打开“自定义屏蔽用户”；在弹窗中全选并复制完整内容，然后点“取消”。如果菜单不存在，先记录当前开关状态，临时开启“屏蔽指定用户”并刷新页面。
3. 同样复制“自定义屏蔽关键词”的完整内容；关键词之间的 `|` 分隔符需要保留。如果菜单不存在，临时开启“屏蔽指定关键词”并刷新页面。
4. 记录原版菜单中各功能的开关状态，以及“屏蔽低赞低评”和“屏蔽指定类别”中的自定义选项。
5. 安装本维护版，先停用原版，避免两个脚本同时修改同一个知乎页面。
6. 在维护版菜单中分别粘贴自定义屏蔽用户和关键词，并按记录恢复其他开关与数值。
7. 刷新知乎，检查普通信息流和“等你来答”的四个分类；确认无误后再决定是否删除原版。

迁移过程中不要先删除原版。Tampermonkey 中停用的原版可作为配置备份，出现遗漏时可以随时重新启用核对。

## 上游已有能力

当前维护版从上游基线继承的主要能力包括：

- 按用户、关键词、内容类别、赞同数和评论数过滤内容；
- 通过 Userscript 菜单维护屏蔽用户、屏蔽词及功能开关；
- 收起回答与评论、快捷返回顶部；
- 清理登录弹窗、高亮链接、搜索热门和标题消息；
- 展开问题描述、显示问题作者和完整时间；
- 使用原图、处理站外直链，以及区分问题与文章等。

完整行为以仓库根目录的 [`Zhihu-Enhanced.user.js`](./Zhihu-Enhanced.user.js) 为准。

## 开发与验证

本项目保持单文件、零构建、零运行时依赖。修改后至少运行：

```powershell
node --check .\Zhihu-Enhanced.user.js
node --test
```

涉及页面选择器、动态加载或内容过滤时，还应在 Tampermonkey 中完成对应页面的手工验证。
语法检查不能替代浏览器功能验证。

`2.3.36` 的回归测试使用 Node 内置测试框架和模拟 DOM，覆盖混合节点、包装节点、评论原文恢复、
邀请区等待超时/路由取消/正常展开折叠，以及批次查询次数。尚未完成 Tampermonkey 实测：
热榜动态加载、高亮链接清理、评论点击恢复、邀请区与 SPA 切换、悬浮评论关闭，以及“等你来答”四个分类仍需浏览器验证。
本次环境中默认 `node --test` 因子进程 `spawn EPERM` 无法运行，使用
`node --test --test-isolation=none` 执行测试；该结果不代表真实浏览器兼容性验证。
